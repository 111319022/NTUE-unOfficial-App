它到底怎麼運作？

給要把帳號密碼交出去之前，想先搞清楚的人看的技術說明。

三句話版本

  • 這個 App 就是一個幫你按按鈕的瀏覽器：它在你的手機上用你的帳號登入學校官方網站，把頁面抓下來、重新排版成好看的原生畫面。
  • 沒有中間站。我（開發者）沒有架任何伺服器，你的帳密與成績課表從來沒有經過我這裡——不是「我保證不看」，是結構上沒有地方可以看。
  • 整包程式碼公開在 GitHub，任何懂 Swift 的同學都可以自己審、自己編譯，不用相信我的人品。

1. 資料是怎麼流動的

從你按下「登入」到課表出現在畫面上，完整流程是這樣：

  1. 你在 App 裡輸入學號與密碼你的手機 跟你在 Safari 打開校園入口網打字，是同一件事。
  2. 帳密以 HTTPS 直接送到學校官方登入伺服器→ protocol.ntue.edu.tw 走的是學校原本的 OpenID Connect 登入流程（跟網頁版同一支 API、同一個網址）。這段連線的另一端只有學校，中間沒有任何我的機器。
  3. 學校驗證通過，發一組登入 Cookie 回到你的手機你的手機 Cookie 存在系統的 Cookie 儲存區，跟瀏覽器的行為一樣。
  4. App 帶著這組 Cookie，去抓你有權限看的頁面→ nsa.ntue.edu.tw · md.ntue.edu.tw iNTUE 校務系統要成績、課表、請假、缺曠；Moodle 要作業與課程公告。抓回來的是原始 HTML 網頁，跟瀏覽器收到的一模一樣。
  5. 在手機上用 SwiftSoup 把 HTML 解析成資料你的手機 從一堆網頁標籤裡挑出「星期三第 3 節是 xxx」這種欄位。這一步完全離線，只是在處理剛剛下載回來的那串文字。
  6. 結果存在裝置本機，畫成原生畫面你的手機 快取放在 App 沙盒與 App 群組（給小工具、Live Activity 讀），所以下次開 App 不用等 10 秒。登出即清除。

整條路徑上，資料的落點只有兩個：學校的伺服器和你的手機。

2. 為什麼開發者「無法」看到你的資料

「我不會偷看」是承諾，承諾可以被打破。下面這幾點是可以驗證的事實：

  • 沒有後端伺服器。這個專案沒有任何 API 主機、資料庫或 log 伺服器。資料想外流也得先有個地方可流。
  • App 只連得到三個學校網域（protocol.ntue.edu.tw、nsa.ntue.edu.tw、md.ntue.edu.tw）與 Apple 的服務。原始碼裡把所有 https:// 開頭的字串抓出來就這幾個，沒有第四個目的地。
  • 沒有任何分析 / 廣告 / 當機回報 SDK。沒有 Google Analytics、沒有 Firebase、沒有 Facebook SDK，也沒有廣告識別碼。
  • 只有一個第三方套件（SwiftSoup，見下），而它是一個不連網的純解析函式庫。

你可以怎麼自己驗證

  • 在 GitHub 上搜尋整個專案的 https:// 或 URLSession，看它到底連去哪裡。
  • 看 App Store 頁面的「App 隱私」標籤：本 App 標示為未收集任何資料。
  • 真的想較真：用 Charles / Proxyman 之類的工具側錄手機流量，看看封包往哪送。
  • 最徹底的做法：把原始碼抓下來，用 Xcode 自己編譯裝到自己手機上——那份就完全在你的掌握裡。

3. 帳號密碼存在哪裡

  • 存在 iOS 系統的 Keychain（鑰匙圈）——就是 Safari 幫你記密碼用的那個加密儲存區，由系統與裝置硬體保護，其他 App 讀不到。
  • 為什麼要存？學校的登入狀態很短命，不存的話你每次開 App、每次小工具想更新課表都得重打一次密碼。存下來只為了「悄悄重新登入」。
  • 密碼只會被送到一個地方：學校官方登入網址 protocol.ntue.edu.tw，而且是 HTTPS 加密連線。
  • 登出會刪掉本機密碼並清空所有快取；刪除 App 會把 Keychain 裡的資料一起帶走。

4. 唯一的雲端：一份公用設定檔

老實說有一個地方會連到 Apple 的雲端服務（CloudKit）。講清楚它是什麼：

存了什麼用途方向
學期行事曆（開學日、期末日、選課日）首頁「學期倒數」、判斷是不是放假中雲端 → 你的手機
校園活動（校慶、考試週…）校園行事曆頁面雲端 → 你的手機
最低版本設定舊版本有嚴重錯誤時提示更新雲端 → 你的手機

這是一個公開、唯讀的資料庫，讓我可以改開學日期而不用發新版 App。它是單向往下讀的： 你的任何個人資料、帳密、成績課表都不會被寫上去，也沒有程式碼在做這件事。 （App 裡的開發者後台則是用 iCloud 帳號的雜湊白名單擋住，一般使用者看不到、也打不開。）

5. 有些畫面是直接開官方網頁

凡是會寫入學校系統的操作（例如請假申請），App 不自己代送表單，而是在內建瀏覽器裡載入學校官方的那一頁，讓你自己填、自己送出。修業進度、在學證明的 PDF 也是直接抓官方產生的檔案。

理由很簡單：會影響你學籍的事情，寧可讓官方頁面自己處理。我不想因為某個欄位猜錯，害你送出一張莫名其妙的假單。這也表示 App 沒有能力替你改任何資料——它做的事，你自己開瀏覽器也做得到。

6. SwiftSoup 是什麼？為什麼可以放心

SwiftSoup 是一個開源的 HTML 解析函式庫，它是 Java 世界用了十幾年的老牌工具 jsoup 的 Swift 版移植，作者 scinfu，採 MIT 授權。

它的工作只有一件：把一段 HTML 文字，變成程式可以查詢的結構——像是「找出這個表格裡所有的列」。打個比方，網頁抓回來是一整張報紙，SwiftSoup 是那把幫你把要看的那一欄剪下來的剪刀。

  • 它不連網路：SwiftSoup 從頭到尾只處理已經下載回來的字串，本身不發任何請求。網路的部分是 Apple 官方的 URLSession 在做。
  • 它碰不到你的密碼：帳密走的是 Keychain 與登入請求，跟解析器完全不同路徑。
  • 它是本專案唯一的第三方相依：相依愈少，供應鏈風險愈小——沒有一堆你沒聽過的套件在背後跑。
  • 版本被鎖死：Package.resolved 記錄了精確的版本與 commit 雜湊（2.13.5），任何人編譯出來的都是同一份程式碼，套件作者也無法偷偷替換掉已發布的版本。
  • 原始碼在此：github.com/scinfu/SwiftSoup，全球有大量 App 在用，是被長期檢視過的專案。

整份原始碼（每一行網路請求、每一個存檔位置）都公開在 GitHub，你可以：

8. 對學校系統會不會造成負擔？

  • App 抓的頁面就是你自己打開瀏覽器會看的那幾頁，沒有繞過任何權限、沒有碰別人的資料——你看不到的東西，App 也一樣看不到。
  • 內建請求佇列限制同時連線數（最多 3 個），並讓你正在等的畫面優先，不會對學校伺服器連發請求。
  • 資料有快取，過去學期讀過一次之後就離線供應，整體請求量比你自己一頁頁點還少。

9. 誠實的限制

  • 這是學生個人作品，非學校官方，學校沒有背書，也不負任何責任。
  • 資料一律以官方系統為準。畢業學分、成績這類會影響你的事情，請回官方系統再確認一次。
  • 學校網站改版時，解析可能會壞掉（畫面空白或資料怪怪的）。遇到請回報，我會修。

10. 常見疑慮

你會不會把我的密碼存起來偷用？

做不到。沒有伺服器可以收，密碼只在你手機的 Keychain 與學校登入頁之間往返。這件事不用相信我，去看原始碼裡 AuthService.swift 的每一個網址就知道。

這樣算不算「駭」學校系統？

不算。App 是用你自己的帳號、看你自己本來就看得到的頁面，跟你開 Safari 登入完全一樣，沒有嘗試繞過任何驗證或存取別人的資料。它只是把排版做得比較好看。

用了會不會被學校停權？

行為上等同正常瀏覽，也有限制連線數避免造成負擔。不過這畢竟是非官方工具，使用風險自負；若學校日後有相關規範，請以學校的規定為準。

換手機、登出之後資料會怎樣？

登出：立刻刪除本機密碼並清空所有快取。刪除 App：連 Keychain 裡的帳密一起消失。因為沒有雲端備份你的資料，換手機就是重新登入一次而已。

我不是資工系的，看不懂程式碼怎麼辦？

可以請任何一位寫程式的朋友幫你看——這正是開源的意義：你不需要信任我，只需要有人能查。也歡迎直接寫信問我。
